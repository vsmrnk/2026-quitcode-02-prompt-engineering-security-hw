# Безпечний рефакторинг (поведінка незмінна)

## Роль

Інженер, що робить рефакторинг маленькими кроками під зеленими тестами. Твоє
кредо: рефакторинг НЕ змінює спостережувану поведінку.

## Мета

Покращити внутрішню структуру `app/src/quote.ts` (читабельність, дублювання)
без жодної зміни публічної поведінки.

## Контекст

- **Модуль:** `app/src/quote.ts`.
- **Захисна сітка:** `app/src/quote.test.ts` — має бути зеленою ДО і ПІСЛЯ.
- **Команди:** `cd app && npm test`, `cd app && npm run typecheck`.
- Домен: суми — цілі в центах.

## Обмеження

- Публічні сигнатури (`estimateTotalCents`, `splitInstallments`, `formatMoney`,
  експортовані типи/константи/помилки) НЕ змінюються.
- НЕ додавай залежностей. НЕ змінюй тести, щоб «підігнати» їх під новий код —
  якщо тест доводиться міняти, це вже не рефакторинг: зупинись і поясни.
- Один коміт-крок = одна структурна зміна.
- Якщо безпечного покращення немає (код уже чистий) — **не вигадуй churn**:
  так і скажи й не роби змін. Порожній рефакторинг кращий за косметичний.

## Acceptance criteria

- [ ] `cd app && npm test` — зелений і ДО, і ПІСЛЯ (та сама кількість тестів).
- [ ] `cd app && npm run typecheck` — без помилок.
- [ ] Жодна публічна сигнатура не змінилась (порівняй експорти до/після).
- [ ] Файл тестів `quote.test.ts` не змінено.
- [ ] У підсумку перелічені зміни й підтверджено, що поведінка та сама.

## Формат відповіді

1. План рефакторингу (список кроків, кожен — одна зміна).
2. Діф `quote.ts`.
3. Вивід `npm test` до і після (щоб було видно однакову кількість зелених).

## Stop

Після зелених тестів і незмінних сигнатур — зупинись. Не додавай нову
функціональність під виглядом рефакторингу.

## Слід запуску (Task A, доказ)

Реально прогнано на `app/src/quote.ts` окремим агентом. **Чесний результат:
змін не зроблено** — агент перевірив і повідомив, що код уже чистий: спільна
валідація `hours`/`rateCents` уже винесена в приватний хелпер
`assertFiniteNonNegative`, а решта перевірок одноразові й структурно різні, тож
«узагальнений валідатор» був би контрприкладом надмірної абстракції. За власним
правилом промпту (пункт 2: «якщо немає безпечного покращення — не вигадуй
churn») агент коректно **утримався від змін**. `npm test` до і після — 46
зелених, `quote.test.ts` не торкнуто, публічні сигнатури незмінні. Це і є
правильна поведінка safe-refactor промпту: інколи найкращий рефакторинг — жодного.
