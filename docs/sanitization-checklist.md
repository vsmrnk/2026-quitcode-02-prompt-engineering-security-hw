# Чек-ліст санітизації даних для роботи з AI

Робочий документ команди. Проходьте його щоразу, перш ніж дати AI-моделі
будь-який документ клієнта, лог, вигрузку чи бриф. Це процедура, не есе: ціль у
тому, щоб модель розуміла задачу, але не бачила жодного реального значення.

Головне правило одразу. Якщо після маскування задача перестала бути зрозумілою —
замаскували зайве. Якщо в тексті лишилось хоч одне реальне значення з 🔴 —
замаскували замало. Обидві помилки однаково погані.

## 1. Класифікація (світлофор)

| Категорія | Приклади | Куди можна |
|---|---|---|
| 🔴 Секрети | API-ключі, токени, connection strings, паролі, PAT, n8n/CI credentials, приватні ключі | **нікуди**; лише out-of-band через env |
| 🔴 PII | ПІБ, email, телефон, адреса, месенджер-хендли, № документів, геолокація | нікуди в публічну модель |
| 🔴 Продакшн-дані | вигрузки таблиць, дампи БД, логи з даними користувачів | нікуди; замінити синтетикою |
| 🟡 Внутрішня комерція | маржа, собівартість, ставки, умови угод, дедлайни-важелі | лише no-train / enterprise (див. §7) |
| 🟡 Внутрішня топологія | назви систем, схеми БД, внутрішні хости, назви гілок/сервісів, стек | лише no-train / enterprise |
| 🟢 Постановка задачі | опис проблеми, критерії приймання, обсяги **без даних**, формати полів | будь-яка модель |

Документ належить до найвищої присутньої в ньому категорії: один 🔴-рядок робить
весь файл 🔴, поки ви його не приберете. За цим і обирається інструмент (§7).

---

## 2. Де шукати (пошук перед очищенням)

Прогнати текст цими патернами — **до** того, як його побачить модель:

```bash
# секрети та підключення
grep -nEi '(api[_-]?key|secret|token|password|passwd|bearer|authorization)' FILE
grep -nE  '(postgres|mysql|mongodb|redis|amqp)://|xox[baprs]-|sk-|pat[A-Za-z0-9]|AKIA[0-9A-Z]{16}|-----BEGIN' FILE
# PII
grep -nE  '\+?[0-9][0-9()\-\s]{8,}|[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+|@[A-Za-z0-9_]{3,}' FILE
# внутрішні хости / бази
grep -nEi '\.(internal|local|example\.test)|base[_-]?id|app[A-Za-z0-9]{10}' FILE
```

Корисні інструменти для автоматизації кроку: `gitleaks`, `detect-secrets`,
`trufflehog`, будь-який DLP-скан. Regex ловить формати, ці — ще й ентропію.

## 3. Як маскуємо (4 техніки)

| Техніка | Коли | Приклад |
|---|---|---|
| **redaction** | значення не потрібне задачі взагалі | `<REMOVED>` |
| **masking** | важлива **форма**, не значення | `+380 (XX) XXX-XX-XX`, `****-1234` |
| **synthetic** | потрібні правдоподібні дані того ж формату | `[CLIENT_1]`, `orders@example.test`, вигадані 2-3 рядки |
| **out-of-band** | секрет не потрапляє в текст **взагалі** | `<SECRET_OUT_OF_BAND>` → значення лише в `env` |

Плейсхолдери тримайте стабільними: якщо той самий клієнт згадується тричі — усюди
`[CLIENT_1]`, а не `[CLIENT_1]/[CLIENT_2]/[X]`, інакше модель не зрозуміє, що це
одна сутність.

І зберігайте структуру, що несе задачу. Три різні формати телефону, наявність
ФОП, адреса з квартирою й без — це фактично вимоги до валідації. Замінюйте
значення, але лишайте варіативність формату.

---

## 4. Креденшели — окремий, найсуворіший кейс

- Ключі, токени й паролі не потрапляють у документ чи промпт ніколи — навіть
  замасковані наполовину. Половина ключа — це витік половини ключа.
- Замінюємо на іменований плейсхолдер і документуємо змінну оточення:
  `CRM API key → <SECRET_OUT_OF_BAND>` (значення в `CRM_API_KEY`).
- Модель має знати, що інтеграція є і яка її роль, а не її ключ.
- Якщо ключ уже десь засвітився (в чаті, скріні, комміті), він скомпрометований —
  ротуйте його, а не «видаляйте повідомлення». Видалення не відкликає доступ.

---

## 5. Перед тим, як натиснути Enter (фінальний gate)

- [ ] Пройшов пошуком з §2 — жодного збігу не лишилось
- [ ] Жодного справжнього телефону / email / ПІБ / адреси / хендла
- [ ] Жодного ключа/токена/connection string — усі out-of-band
- [ ] Вигрузки з прода замінені синтетичними рядками того ж формату
- [ ] 🟡-контент (маржа, назви систем) прибрано або узгоджено з §7-інструментом
- [ ] Перечитав очима: **задача все ще зрозуміла** без оригіналу
- [ ] Обраний інструмент відповідає найвищій категорії в документі (§1, §7)

---

## 6. Санітизація «руками агента» — зручність, не гарантія

Спокусливо попросити AI «замаскуй чутливе в цьому брифі». Але щойно агент прочитав
оригінал, оригінал уже пішов у модель, і вправа втратила сенс.

- Детермінований крок (regex / `detect-secrets` / DLP) робиться локально й до
  того, як текст побачить будь-яка модель. Оце і є гарантія.
- AI можна залучати хіба для підсвічування кандидатів на маскування — але на
  копії, у no-train інструменті, і його висновок усе одно перевіряє людина.
- Оригінал і санітизована версія — різні файли. Оригінал не комітиться й у
  публічну модель не вставляється ніколи.

## 7. Інструмент під категорію

| Категорія | Інструмент / режим | Чому |
|---|---|---|
| 🟢 | звичайна підписка (публічний чат) | немає чутливого — ризик нульовий |
| 🟡 | **enterprise / no-train** (напр. Claude Team/Enterprise, API з zero-retention, або локальна модель) | внутрішня комерція й топологія не мають потрапити в тренувальні дані |
| 🔴 | AI не використовуємо, поки не знято до 🟡/🟢 | секрети й PII не передаємо жодній моделі; спершу санітизація |

Тут важливо: самого «no-train» для 🟡 не досить. Перш ніж пускати 🟡-дані в
інструмент, підтвердіть усі пункти нижче — будь-який непідтверджений означає, що
ставимося до інструмента як до 🔴:

- [ ] Non-training — договірна гарантія, що дані не йдуть у навчання
- [ ] Retention — короткий і відомий строк зберігання (в ідеалі zero-retention)
- [ ] Logging — що саме логується з промптів і хто має доступ до логів
- [ ] Deletion — право й SLA на видалення за запитом
- [ ] DPA / sub-processors — підписаний DPA і відомий список субпроцесорів
- [ ] Region / residency — регіон обробки даних

Це стосується й локальних моделей: Ollama чи self-hosted прибирають вихід даних
за периметр, але retention, logging і deletion усе одно визначаються вашою
інфраструктурою — їх треба налаштувати, а не вважати наявними за замовчуванням.

### Який tier для 🟡-даних і чому

Для 🟡 (маржа, собівартість, назви внутрішніх систем, схеми БД) ми беремо
інструмент із контрактною no-train політикою та коротким retention — enterprise-
підписку на кшталт Claude Team/Enterprise або API з zero-data-retention. Для
найчутливішого 🟡 — локальну модель (Ollama / self-hosted).

Логіка така. 🟡 не секрет сам по собі — це не ключ. Але його накопичення в
тренувальних даних сторонньої моделі — це довгостроковий витік конкурентної
переваги, який уже не відкликати. Публічна безкоштовна модель відпадає не тому,
що «зараз витече», а тому, що немає договірної гарантії, що дані не підуть у
навчання. Локальна модель прибирає навіть теоретичний вихід за периметр, але
коштує якістю й інфраструктурою, тож її беремо точково, під найгостріше 🟡. Що
ближче дані до 🔴, то ближче інструмент до локального.
